### КЛАСТЕР 1: КОДОВЫЙ ИНТЕЛЛЕКТ (пересечение!)
```

       │  • Семантический поиск функций/классов        │
       │  • Граф зависимостей                          │

                    CodeRAG — npm пакет (легче)         │
```

### КЛАСТЕР 2: ОРКЕСТРАЦИЯ АГЕНТОВ (дополнение)
```
Hermes ─── использует ─── dnts-agent (очередь задач)
  │                           │
  │ использует              LangGraph (DAG pipelines)
  │                           │
  │ может управлять ────── Ralph (outer harness)
  │ через ralph -H          │
  │                         PicoClaw (второй агент)
  │
  → ВСЕ РАЗНЫЕ, НО:
    Hermes = водитель
    LangGraph = строит маршрут
    Ralph = контроллер
    PicoClaw = второй водитель
```

## Проблемные пересечения (что дублируется)

| Кластер | Компоненты | Проблема |
|---------|-----------|----------|
| **Кодовый интеллект** | codebase-memory-mcp + CodeRAG + dnts-memory project_index | 3 системы для одного — индексации кода |
| **Поиск** | DuckDuckGo + SearXNG | 2 бэкенда, работает 1 |
| **Memory** | dnts-memory KG + fact_store + memory tool + Mem0 (dead) | 4 системы памяти, активны 3 |
| **Оркестрация** | Hermes + LangGraph + Ralph + PicoClaw | 4 инструмента для управления агентами |

## Рекомендация по соединению (как с LangGraph + codebase-memory)

Лучшая связка сейчас:

```
LangGraph строит пайплайн → вызывает codebase-memory-mcp как источник данных
                          → использует dnts-core для файловых операций
                          → через dnts-reason проверяет результат
                          
Hermes управляет всем → использует dnts-agent для фоновых задач
                     → Ralph для мониторинга/outer-loop
                     → PicoClaw как лёгкий MCP-host при необходимости
```

Из дублирующихся кластеров — **кодовый интеллект** требует решения: 3 инструмента (codebase-memory-mcp, CodeRAG, dnts-memory project_index) делают одно и то же. codebase-memory-mcp v0.8.1 — самый мощный (14 tools, 158 языков, LSP, граф).
