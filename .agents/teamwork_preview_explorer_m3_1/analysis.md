## 3. Atomic Markdown Note Specification

Each Zettelkasten note generated by `vazus_core/zettelkasten_exporter.py` MUST be strictly self-contained, atomic (focusing on a single claim, entity, or protocol), and follow the standard structure below.

### 3.1 YAML Frontmatter Schema
The note MUST begin with YAML frontmatter containing 7 mandatory attributes:

```yaml
---
id: "thesis_4210a7ba"
title: "Vitamin D3 Co-factor Protocol (K2 and Magnesium)"
domain: "kgb_analytics"
tags:
  - iad
  - thesis
  - vitamin_d3
  - cofactors
node_type: "ThesisNode"
confidence_score: 0.85
created_at: "2026-07-24T12:56:53Z"
---
```

#### Field Definitions & Data Types:
- `id` (string, required): Unique identifier from `kg_nodes.id` (e.g. `thesis_4210a7ba`, `protocol_47cb432f`, `ast:vazus_core_supergraph_linker`).
- `title` (string, required): Human-readable title derived from `name` or cleaned statement.
- `domain` (string, required): Operational domain (`kgb_analytics`, `ast_code`, `multimodal_av`, `telegram_discussion`, `general`).
- `tags` (YAML array of strings, required): Categorical tags parsed from `kg_nodes.tags` plus domain and node_type tags.
- `node_type` (string, required): Entity class (`ThesisNode`, `ProtocolNode`, `WikiNote`, `CodeNode`, `MediaScene`).
- `confidence_score` (float, required): Confidence rating between `0.0` and `1.0` (from `properties.confidence` or `properties.confidence_score`, default `0.85`).
- `created_at` (string, required): ISO-8601 UTC timestamp (`YYYY-MM-DDTHH:MM:SSZ`).

## 4. Rule Systems for Zettelkasten Generation

### 4.1 Rules for Actionable Checklist Generation (`- [ ]`)

Checklists bridge passive analytical knowledge with active operational execution.

1. **ProtocolNode Mapping**:
   - Extract `action_instruction`, `steps` (array), `frequency_periodicity`, and `safety_warnings` from node properties.
   - Format each step as:  
     `- [ ] Action: <step_text> [Periodicity: <frequency_periodicity>]`
   - Format safety warnings as:  
     `- [ ] Safety Warning: <warning_text>`
2. **ThesisNode Mapping**:
   - For `HYPOTHESIS`:  
     `- [ ] Verification: Conduct empirical benchmark or SMT Z3 contract test for thesis statement.`
   - For `ACCEPTED`:  
     `- [ ] Operational: Integrate thesis rule into active pipeline execution context.`
   - For `REJECTED` / `CONTRADICTED`:  
     `- [ ] Audit: Review and purge disproved claim from active reasoning prompts.`
3. **AST / Code Node Mapping**:
   - `- [ ] Code Audit: Verify test coverage and lint status for module.`
   - `- [ ] Contract Verification: Run SMT Z3 solver on function pre/post-conditions.`

---

### 4.2 Rules for 3+ Bidirectional Wikilinks (`[[Wikilinks]]`)

Every note MUST have at least **3 valid wikilinks** in `## Related Notes`.

#### Link Discovery Pipeline:
1. **Direct Graph Edges (`kg_edges`)**:
   - Query all edges where `source_id == node.id` or `target_id == node.id`.
   - Map edge relations (`CAUSES`, `REQUIRES`, `CONTRADICTS`, `BELONGS_TO`, `NEXT_SCENE`) into link items:  
     `- [[Target_Note_Title]] — Relation: <RELATION> (Strength: <strength>)`
2. **768D Vector Similarity Fallback (`SuperGraphLinker`)**:
   - If direct graph edges yield `< 3` links, calculate cosine similarity between `node.embedding_json` and stored embeddings in `kg_nodes`.
   - Select top candidates with similarity score >= 0.15.
3. **Domain Hub Fallback**:
   - If total links remain `< 3`, add canonical domain fallback notes:
     - `kgb_analytics` -> `[[kgb_analytics_Memory_Hub]]`, `[[SuperGraph_OS_Architecture]]`
     - `ast_code` -> `[[ast_code_Memory_Hub]]`, `[[AI_Lessons_and_Mistakes]]`
     - `multimodal_av` -> `[[multimodal_av_Memory_Hub]]`

#### Bidirectionality Enforcement Algorithm:
When generating Note A which links to Note B (`[[Note_B]]`):
1. The exporter checks if Note B exists on disk (`<wiki_dir>/<note_b_slug>.md`).
2. If Note B exists, the exporter verifies if `[[Note_A]]` is present in Note B's `## Related Notes`.
3. If missing, Note B is updated in-place (or scheduled for backlink injection) by appending `- [[Note_A]] — Relation: INVERSE_<RELATION>` under `## Related Notes`.

## 5. Output Format & File Naming Conventions

### 5.1 Directory Hierarchy
Notes MUST be written to both primary and secondary wiki vaults:
- Primary: `C:\vazus\services\memory\semantic\wiki\`
- Mirror: `C:\vazus\memory\semantic\wiki\`

### 5.2 Naming Rules
1. **Slugified Title Format** (Preferred):
   - Rule: Convert `title` / `name` to lowercase alphanumeric string with single underscores replacing spaces and special characters.
   - Example: Title `"Vitamin D3 Co-factor Protocol (K2 and Magnesium)"` -> `vitamin_d3_co_factor_protocol_k2_and_magnesium.md`.
2. **ID-Based Format** (Fallback when title is empty or non-ASCII edge case):
   - Rule: `wiki_<id>.md` or `<node_type_slug>_<id>.md`.
   - Example: `thesis_4210a7ba.md`.
3. **Sanitization Constraints**:
   - Max filename length: 64 characters (prevents Windows `MAX_PATH` length errors).
   - Strip leading/trailing underscores and invalid Windows path characters (`<>:"/\|?*`).
