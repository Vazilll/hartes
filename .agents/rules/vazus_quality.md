# Vazus Quality & Lifecycle Invariants

## 1. Dead Code Prevention (Gate-5 Vulture Invariant)
- Любые неиспользуемые аргументы в сигнатурах функций, коллбэках сигналов (`SIGINT`), интерфейсах хуков и адаптерах ОБЯЗАНЫ иметь префикс нижнего подчеркивания:
  - `*_args`, `**_kwargs` вместо `*args`, `**kwargs`
  - `_sig`, `_frame` вместо `sig`, `frame`
- Это исключает ложноположительные блокировки pre-commit хука при проверке `python -m vulture --min-confidence 90`.

## 2. Context Watchdog & Lifecycle Compression
- Агент обязан учитывать пороги сторожа сессий (`ContextWatchdog`):
  - **400 шагов / 250k токенов**: статус `WARNING` — обязательная семантическая дистилляция через `handoff_generator`.
  - **800 шагов / 450k токенов**: статус `CRITICAL_COMPRESS` — принудительный хендофф и сброс сессионного контекста.

## 3. Git Worktree Isolation Standard (`-w` mode)
- Все спекулятивные мутации, рефакторинг и авто-генерация кода субагентами выполняются в изолированных Git worktrees через `AntigravityWorktreeSandbox` (`C:\vazus\scratch\worktrees`).
- Ветви `sandbox/*` верифицируются через 8 уровней `precommit_gate.py` перед слиянием в `vazus-dev`.

## 4. Anti-Potemkin Reality Check (Инвариант физической верификации)
- **Запрет декларативного триумфализма**: Агент обязан категорически избегать маркетинговых эпитетов («на порядок взрослее», «фазовый переход», «идеальная стабильность») до эмпирического стресс-тестирования в боевых условиях.
- **Physical Asset Verification**: Запрещено рапортовать об ускорении на NPU/GPU или интеграции локальных LLM без проверки:
  1. Реального физического наличия файлов весов (`.bin` / `.safetensors` / `.xml`) на диске.
  2. Успешного прогона тестового инференса на реальном железе (не заглушки `[NPU_LM_UNAVAILABLE]`).
- **Mathematical Soundness Gate**: В Z3 SMT и нейросимволических синтезаторах ЗАПРЕЩЕНО добавлять вспомогательную лемму $L$ в решатель опровержения $(A \wedge \neg P)$ без предварительного доказательства $A \implies L$. Ложные доказательства из-за противоречивых посылок считаются критическим дефектом P0.
- **Zero Potemkin Services**: Если сервис (Data Fabric, API, Sidecar) объявлен работающим, агент обязан проверить открытый порт (`netstat` / `Test-NetConnection`) и успешный HTTP-ответ без опоры на скрытые статические JS-массивы.

## 5. Personal Repositories & Closed Scope Invariant
- **Strict Scope Boundaries**: Все мутации кода, коммиты и слияния PR ограничены ИСКЛЮЧИТЕЛЬНО личными репозиториями пользователя:
  - `C:\vazus` (`vazus SuperGraph OS`)
  - `C:\vazus\hartes` (`Vazilll/hartes`)
  - `C:\vazus\apps\CROC-DREAM-NetOps-Platform` (`git@github.com:Vazilll/Croc.git`)
- **Запрет внешних хакатонов**: КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО вносить изменения, запускать скрипты или отправлять сетевые запросы в публичные хакатоны/контесты (включая репозитории `xadecoride`), если нет прямого явного указания.
- **Full Branch Synchronization**: При слиянии веток из GitHub PR агент обязан создавать локальные tracking-ветки (`git branch --track`) во всех затронутых репозиториях пользователя, чтобы изменения были доступны для локального аудита.
