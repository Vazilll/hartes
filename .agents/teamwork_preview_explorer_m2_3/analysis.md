Milestone 2 (R2) of the `vazus` SuperGraph OS extension requires building `vazus_core/kgb_analytical_extractor.py`, an analytical knowledge extraction engine leveraging Soviet/Russian **ИАД (Информационно-Аналитическая Деятельность / Information-Analytical Activity)** and **ACH (Analysis of Competing Hypotheses)** methodologies.

1. **`ThesisNode`**: Core analytical claims, hypotheses, scientific assertions, and domain facts.
2. **`ProtocolNode`**: Actionable procedures, routines, step-by-step guidelines, and operational algorithms.

   - **`CAUSES`**: Multi-cause chains and causal relationships ($A \implies B$).
   - **`REQUIRES`**: Protocol dependencies and prerequisite co-factors ($A \text{ REQUIRES } B$).
   - **`CONTRADICTS`**: Conflicting hypotheses and opposing claims ($A \text{ CONTRADICTS } B$).

This report presents a thorough investigation of sample input scenarios across Russian speech transcripts, course notes, and Telegram discussions; specifies exact verification criteria and complex edge cases; designs the architecture for `vazus_core/kgb_analytical_extractor.py`; and delivers a comprehensive, automated test suite specification (`tests/test_kgb_analytical_extractor.py`) for clean implementation by downstream workers.

## 2. Verification Criteria & Complex Edge Case Matrix

The KGB ИАД + ACH engine must handle complex graph topology edge cases to maintain SuperGraph consistency and prevent logical paradoxes.

```
+------------------------------------------------------------------------------------+
|                         EDGE CASE VERIFICATION MATRIX                              |
+-------------------+----------------------------------+-----------------------------+
| Relation Type     | Topological / Logic Constraint    | Verification Action         |
+-------------------+----------------------------------+-----------------------------+
| CONTRADICTS       | Anti-Symmetry & Mutual Exclusion | Bidirectional pair, ACH $I$ |
| CAUSES            | DAG Acyclicity ($\neg \text{Cycle}$) | SMT Z3 topological check    |
| REQUIRES          | Prerequisite Completeness        | Transitive closure check    |
+-------------------+----------------------------------+-----------------------------+
```

### 2.1 Conflicting Hypotheses (`CONTRADICTS` Edge Case)

#### Edge Case Dynamics:
1. **Symmetry Enforcement**: Contradiction between hypothesis $H_A$ and hypothesis $H_B$ is inherently symmetric ($H_A \text{ CONTRADICTS } H_B \iff H_B \text{ CONTRADICTS } H_A$). The database must either store bidirectional edges or query both `(source, target)` directions.
2. **ACH Inconsistency Scoring ($I(H)$)**:
   In ACH methodology, each hypothesis $H_k$ is evaluated against evidence set $E = \{e_1, e_2, \dots, e_n\}$.
   - If evidence $e_i$ is **Inconsistent** with $H_A$ but **Consistent** with $H_B$, $H_A$'s inconsistency rating increases:
     $$I(H_A) = \sum_{e_i \in E} \text{Weight}(e_i) \times \mathbb{I}(e_i \text{ contradicts } H_A)$$
   - The hypothesis with the **lowest inconsistency score** $I(H)$ is selected as `ACCEPTED`, while the contradictory hypothesis with high inconsistency is marked `REJECTED` or `DISPROVED`.

3. **Conditional vs. Strict Contradictions**:
   - *Strict Contradiction*: $A \land \neg A$ (e.g. "Stretching before lifting increases strength" vs "Stretching before lifting decreases peak force"). Result: `CONTRADICTS` edge (strength = 1.0).
   - *Conditional Context Discrepancy*: "Stretching before lifting decreases force" vs "Dynamic mobility warmups before lifting increase power output". Result: No contradiction; distinct nodes with domain/context tags.

### 2.2 Multi-Cause Chains (`CAUSES` Edge Case)

#### Edge Case Dynamics:
1. **Multi-Step Causal DAGs ($A \to B \to C \to D$)**:
   - Causal networks form Directed Acyclic Graphs (DAGs).
   - **Strength Decay**: Total transitive causal strength along chain $P = (n_1, n_2, \dots, n_k)$ is computed via multiplication:
     $$S_{\text{net}}(n_1 \to n_k) = \prod_{i=1}^{k-1} S(n_i \to n_{i+1})$$
     If $S(A \to B) = 0.9$ and $S(B \to C) = 0.8$, then indirect strength $S(A \to C) = 0.72$.

2. **SMT Z3 Acyclicity Invariant**:
   - Physical causality cannot contain directed cycles ($A \text{ CAUSES } B \text{ CAUSES } C \text{ CAUSES } A$).
   - Before inserting edge $(u, v)$ into `kg_edges` with relation `CAUSES`, the engine runs a DFS or Z3 SMT solver check to ensure no path exists from $v$ to $u$. If a cycle is detected, insertion is blocked and flagged as a logical fallacy.

3. **Conjunctive Multi-Cause Nodes ($(C_1 \land C_2) \implies E$)**:
   - Certain effects require multiple co-causes (e.g., High Cortisol AND Low Sleep cause severe Glycogen Depletion). Represented via composite cause nodes or linked sub-causes.

### 2.3 Protocol Dependencies (`REQUIRES` Edge Case)

#### Edge Case Dynamics:
1. **Prerequisite Completeness & Transitive Closure**:
   - If Protocol $P_{\text{advanced}}$ `REQUIRES` Protocol $P_{\text{intermediate}}$, and $P_{\text{intermediate}}$ `REQUIRES` Protocol $P_{\text{basic}}$, executing $P_{\text{advanced}}$ implicitly requires the transitive closure $\{P_{\text{intermediate}}, P_{\text{basic}}\}$.
2. **Co-Factor Prerequisites**:
   - E.g. Boron 10mg supplementation protocol `REQUIRES` 2-week ON / 1-week OFF pulsed cycling to prevent homeostatic rebound desensitization and aromatase up-regulation.
3. **Safety Violations**:
   - Attempting to execute a protocol without satisfying all `REQUIRES` edges with `strength >= 0.9` raises a `ProtocolDependencyError`.

### 3.2 Key Extraction Pipelines Mechanics
1. **Rule-Based Pattern Matchers + Heuristics**:
   - `CAUSES`: Patterns like `(?i)(?:приводит к|вызывает|является причиной|способствует|влечет за собой|приводит к разрыву)`

   - Stores nodes with 768D vector embeddings in `kg_nodes`.
