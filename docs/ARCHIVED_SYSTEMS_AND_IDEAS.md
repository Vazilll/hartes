# Vazus: Реестр законсервированных архитектурных систем и идей (Systems & Ideas Incubator)

Документ создан в рамках принципа **Ponytail** (минимизация сложности, устранение оверхеда, сохранение железобетонного ядра цифрового двойника). Здесь детально описаны экспериментальные модули, их назначение, причины консервации и дорожная карта для их будущего использования.

---

## 1. Каскад пяти жюри верификации (Jury Cascades)
* **Файлы реализации:** `vazus_core/verification/`:
  - `concordia_jury.py` (социально-симулированное согласие агентов)
  - `critic_jury.py` (состязательный критик кода)
  - `dual_jury.py` (парное перекрестное рецензирование)
  - `evidence_jury.py` (оценка доказательной базы утверждений)
  - `sota2027_jury.py` (футуристическая эвристика соответствия стандартам 2027 года)
* **Концепция:**
  - Попытка создать эшелонированную систему многоуровневого арбитража перед любым изменением состояния цифрового двойника или памяти.
* **Причина консервации:**
  - Экстремальный расход токенов и задержка в десятки секунд на тривиальные действия. 5 параллельных жюри часто давали противоречивые вердикты, требуя создания мета-жюри.
  - Для личного двойника критична мгновенность отклика (<1 сек) и детерминизм.
* **Дорожная карта для возрождения:**
  - Свести в один легковесный модуль `DeterministicVerifier`: проверка схемы SQLite, проверка целостности внешних ключей и AST-валидация без привлечения LLM.

## 2. Hermes Agent Engine & Skill Syncer
* **Файлы реализации:** `vazus_core/skills/hermes_agent_engine.py`, `hermes_skill_syncer.py`
* **Концепция:**
  - Двусторонняя интеграция с резидентным агентом Nous Research Hermes: синхронизация выученных скиллов между локальным реестром Vazus и демоном Hermes.
  - Позволяет агенту обучаться на успешных цепочках действий и кристаллизовать их в повторно используемые инструменты.
* **Текущий статус:**
  - Законсервирован до развертывания выделенного демона Hermes на сервере/машине.
* **Дорожная карта для возрождения:**
  - При запуске Hermes Agent подключить `hermes_skill_syncer.py` как двусторонний RPC-мост для импорта скиллов прямо в `vazus_core/skills`.

## 3. Windows Sandbox Controller & WSB-скрипты
* **Файлы реализации:** `tools/sandbox/`, `tools/wsb_sandbox_controller.py`, `vazus_core/sandbox/wsb_sandbox_controller.py`
* **Концепция:**
  - Управление песочницей Windows Sandbox (`.wsb`, PowerShell `Sandbox-Bootstrap.ps1`) для изолированного запуска недоверенного кода.
* **Причина консервации:**
  - Основная рабочая ОС — CachyOS Linux (ядро 6.13+ на Intel Core Ultra 5 125U).
  - В Linux песочницы строятся на нативных `unshare`, `bubblewrap`, `cgroups v2` и OverlayFS в RAM, которые работают в 50 раз быстрее и не требуют виртуализации Windows.
* **Дорожная карта для возрождения:**
  - Использовать только если проект разворачивается на хосте под управлением Windows 11. На Linux использовать `harnet.superposition`.

## 4. Мультимодальные голосовые пайплайны (Jarvis & TTS Podcast)
* **Файлы реализации:** `vazus_core/integrations/telegram_voice_jarvis.py`, `tts_podcast_generator.py`, `voice_thought_engine.py`
* **Концепция:**
  - Генерация аудио-подкастов из учебных конспектов МИРЭА и голосовой интерфейс в Telegram в стиле Jarvis.
* **Причина консервации:**
  - Требует постоянных тяжелых нейросетевых моделей генерации речи (TTS/STT), что сажает батарею ноутбука в мобильном режиме.
* **Дорожная карта для возрождения:**
  - Перевести на локальный NPU Intel AI Boost (OpenVINO / GGUF whisper.cpp), чтобы инференс шел с нулевым энергопотреблением на LP E-ядрах.

## Базовый стандарт «Автомат Калашникова» в Vazus (Неприкасаемое ядро)

1. **`services/memory/vazus.db`**:
   - 810 финансовых транзакций (строгий инвариант).
   - 2552 органических инсайта.
   - База знаний студентов МИРЭА (`study/mirea/`).
   - SQLite FTS5 поиск фактов за 3 миллисекунды.
2. **Локальный MCP SQLite Interface**:
   - Прямой доступ к базе через стандартный протокол инструментов без посредников и лишних слоев абстракции.
